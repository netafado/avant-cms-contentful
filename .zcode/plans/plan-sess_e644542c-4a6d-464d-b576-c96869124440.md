# devclean — a developer-focused Mac cleanup app (Tauri 2)

**Positioning:** "CleanMyMac for developers." Not a heuristic junk scanner — an explicit, curated allowlist of developer toolchain caches that are 100% rebuildable, plus CLI-driven maintenance (Docker, iOS simulators) and Trash emptying. Safety comes from the allowlist being hardcoded, not from clever detection.

**Location:** `/Volumes/BlitzWolf/github/devclean` (sibling folder, own git repo — not inside avant-cms-contentful). Name is a placeholder, trivially renamed.

## Stack

- **Tauri 2.x** — backend in Rust, native shell, ~10 MB binary
- **Frontend:** vanilla TypeScript + Vite (create-tauri-app `vanilla-ts` template) — zero framework deps
- **Rust crates:** `jwalk` (parallel directory size scan), `tauri-plugin-shell` (docker/xcrun/brew/osascript), `sysinfo` (disk free space). Keep the crate list minimal.

**Environment gotchas baked into every command:**
- Rust lives at `~/.cargo/bin` but is not on PATH → prefix all commands with `PATH="$HOME/.cargo/bin:$HOME/.nvm/versions/node/v24.4.0/bin:$PATH"`
- Default `node` (16.17) is too old for Vite → use nvm's 24.4.0 via the same prefix
- First build compiles ~400 crates on the slow external volume — expect a long initial `cargo tauri dev`; incremental rebuilds are fine

## Architecture

```
devclean/
  src-tauri/src/
    categories.rs  — the allowlist: id, name, group, description, rebuild-cost note,
                     risk level, paths[] and/or cleanup command
    scan.rs        — parallel jwalk size scan per category (spawn_blocking),
                     emits scan-progress events; disk free via sysinfo
    clean.rs       — validates requested ids against the allowlist (UI can never
                     delete an arbitrary path), then remove_dir_all + runs CLI
                     cleaners via shell plugin, streams output as events
    trash.rs       — empty Trash via Finder AppleScript (works without Full Disk
                     Access); FDA + direct-delete as fallback path
  src/             — vanilla TS single screen: grouped category list with sizes,
                     checkboxes, disk-free gauge, Clean button, results report
```

## Category allowlist (grouped, from our real cleanup session)

- **JavaScript/Node:** Yarn cache, npm `_cacache`/`_npx`, pnpm cache, Cypress binaries, Playwright browsers (`~/Library/Caches/ms-playwright`)
- **Apple/Xcode:** DerivedData, iOS DeviceSupport, CoreSimulator caches, obsolete simulators, old simulator runtimes (advanced: list UUIDs + sizes, delete only when explicitly ticked — as in our session)
- **Containers:** `docker system prune -af` + `docker builder prune` (named volumes always preserved), with `docker system df` preview first
- **Mobile/JVM:** Gradle caches, CocoaPods cache
- **Python:** pip3 cache purge, uv cache
- **Rust:** cargo registry cache (marked "slows next build" — advanced)
- **Dev apps & system:** Homebrew `brew cleanup --prune=all`, Chrome browser cache (profile untouched), JetBrains/aws/TypeScript caches, Electron `*ShipIt`/updater leftovers (explicit list, no wildcards)
- **Trash:** empty via `osascript -e 'tell application "Finder" to empty trash'`

**Hardcoded never-touch list enforced in clean.rs:** Chrome profile data, `~/Library/Arduino15`, Docker named volumes, Movies/Downloads/Documents.

**Deletion model:** allowlisted caches delete permanently (they're rebuildable by definition; moving 76 GB to Trash defeats the point on a full disk) behind a per-run confirmation listing exact paths and total bytes.

## Milestones (each independently verifiable)

1. **Scaffold** — install tauri-cli, create-tauri-app, verify `cargo tauri dev` opens the window. (First compile is the slow one.)
2. **Scan (read-only)** — categories.rs + scan command + disk-free readout; UI shows grouped sizes and a total. *Verify:* spot-check sizes against `du -sk` for 2–3 paths.
3. **Clean** — confirmation → permanent delete of ticked categories; before/after disk-free report; running-app guard (pgrep Chrome etc.) warns before cache deletion. *Verify:* test against a disposable temp fixture dir first, then one real small cache (TypeScript).
4. **CLI cleaners** — Docker (CLI + daemon detection, `system df` preview, prune) and simulators (`simctl delete unavailable`, runtime list with sizes). *Verify:* docker prune result matches `docker system df` delta.
5. **Trash + Full Disk Access** — AppleScript empty; on EPERM show guidance panel with deep link to System Settings → Privacy → Full Disk Access.
6. **Polish** — persist settings (JSON in app config dir, no store plugin), app icon, `cargo tauri build` → unsigned .app for personal use (notarization only if ever distributed).

## Testing

Manual at each milestone (scan-vs-du sanity, fixture-dir delete test, docker df delta). No unit-test suite in v1 — the risky surface is the allowlist validation in clean.rs, which gets a few Rust unit tests.
